# Research log — Module 6: تقنيات بناء الأوامر

## Research log

| Topic | Sources used | Key findings | Date verified |
|---|---|---|---|
| Task decomposition | Google Gemini prompt design strategies (fetched) | Explicitly recommends breaking complex prompts into simpler ones, chaining sequential steps where output feeds forward, and splitting data for parallel operations. | 2026-09-28 |
| Sub-task completeness | OpenAI prompt engineering guide (fetched) | Advises decomposing a user query into all required sub-requests and confirming each is completed. | 2026-09-28 |
| Reason–act loops | Yao et al. (arXiv:2210.03629) | ReAct alternates reasoning and acting steps; used as the conceptual bridge to agents in Module 7. | 2026-09-28 |
| Structured outputs | OpenAI structured outputs; Gemini structured output (both fetched) | Both platforms offer schema-constrained generation. Crucial teaching point: this fixes **form**, not **content** — a hallucinated value of the correct type still passes. | 2026-09-28 |
| Improper output handling | OWASP Top 10 for LLM Applications 2025, LLM05 | Using model output directly without validation or sanitisation is a top-ten risk; hence "treat model output like untrusted user input". | 2026-09-28 |
| Grounding and retrieval | Lewis et al. (arXiv:2005.11401) | RAG combines retrieval with generation constrained by retrieved passages; used to separate *grounding* (principle) from *retrieval* (mechanism). | 2026-09-28 |
| Structured reasoning | Anthropic prompting docs (chain-of-thought page, fetched) | Vendor guidance on requesting organised reasoning. The course deliberately teaches **structured justification** (rule, evidence, confidence, reproducible steps) rather than requesting exposure of private chain-of-thought, per the course specification §30. | 2026-09-28 |
| Prompt injection | Perez & Ribeiro (arXiv:2211.09527); Greshake et al. (arXiv:2302.12173) | Perez & Ribeiro document early "ignore previous prompt" attacks; Greshake et al. document **indirect** injection through content an LLM-integrated application retrieves — the victim never wrote the instruction. | 2026-09-28 |
| Risk taxonomy | OWASP Top 10 for LLM Applications 2025 (fetched list) | LLM01 Prompt Injection; LLM02 Sensitive Information Disclosure; LLM05 Improper Output Handling; LLM06 Excessive Agency; LLM10 Unbounded Consumption — the five used in this module. | 2026-09-28 |
| Risk management framework | NIST AI 600-1 (Generative AI Profile, 2024) | Referenced as the framework-level companion to OWASP's application-level list. | 2026-09-28 |
| Instruction authority | OpenAI prompt engineering guide (fetched) | Message roles carry **differing authority levels** — the technical expression of the instruction hierarchy taught in 6.4. | 2026-09-28 |

|---|---|---|

| Schema-constrained generation fixes form, not content | Students otherwise believe the problem is solved | 6.2 |
| Structured automation reduces human review | A real risk created by a good practice | 6.2 |

## Modern extensions added

- **OWASP LLM Top 10 (2025)** mapped onto concrete university scenarios rather than cited abstractly.
- **Tool-parameter data leakage** (LLM02) — a leakage path students rarely consider.
- **Unbounded consumption** (LLM10) as a cost-and-availability risk, not just a security one.
- **Defence in depth with named failure modes** for each layer, including the human layer.

## To verify / limitations

- **OWASP URL moved.** `genai.owasp.org/llm-top10/` returns 404; the canonical list is at `genai.owasp.org/llm-top-10/` (with hyphens), reached from the OWASP project page. Recorded correctly in `references.yml`.
- **Vendor documentation changes.** Structured-output features and the Anthropic reasoning guidance are described only as read on 2026-09-28, with URLs recorded. Exact API details are deliberately **not** taught, since they change.
- All injection examples in the lab are **written for teaching**; none is copied from a live attack, and the module is framed defensively with an explicit note that testing systems you do not own may be unlawful.
- The claim that separation "is necessary but not sufficient" is argued from documented attack patterns (Greshake et al.) rather than from a measured failure rate; no success-rate figure is claimed.
- The permission tables are **teaching designs**, not audited security architectures; they are labelled as classroom exercises.
